
### IPv4 و IPv6: فرق‌ها و نکات عملی

| ویژگی               | IPv4                                                     | IPv6                                                               |
| ------------------- | -------------------------------------------------------- | ------------------------------------------------------------------ |
| **طول آدرس**        | ۳۲ بیت (حدود ۴ میلیارد آدرس)                             | ۱۲۸ بیت (۳.۴×۱۰^۳۸ آدرس)                                           |
| **نمایش**           | چهار عدد ۸ بیتی با نقطه (`192.168.1.1`)                  | هشت گروه ۱۶ بیتی هگز (`2001:db8::1`)                               |
| **پیکربندی خودکار** | DHCP                                                     | SLAAC (Stateless Address Autoconfiguration)                        |
| **پشتیبانی NAT**    | رایج (برای کمبود آدرس)                                   | در طراحی بدون NAT؛ در عمل در بعضی سناریوها NAT66 هم استفاده می‌شود |
| **امنیت درونی**     | اختیاری (IPsec اضافه می‌شود)                             | پشتیبانی IPsec در طراحی IPv6 پیش‌بینی شده (در عمل اغلب اختیاری)    |
| **بسته‌بندی**       | حداقل اندازهٔ دیتاگرام قابل پشتیبانی ۵۷۶ بایت (RFC 1122) | حداقل MTU لینک ۱۲۸۰ بایت؛ هدر ساده‌تر                              |

**تصمیم‌گیری عملی برای بک‌اند:**

- سرویس‌های امروزی باید حتماً **dual-stack** باشن (هم IPv4 و هم IPv6).
- توی کد، برای گوش دادن روی هر دو پروتکل: در لینوکس با تنظیم پیش‌فرض (`IPV6_V6ONLY=0`) بایند به `::` می‌تونه هم اتصالات IPv6 و هم IPv4 (به‌صورت IPv4-mapped) رو بپذیره؛ در برخی توزیع‌ها (مثل دبیان) یا ویندوز ممکنه فقط IPv6 باشه، پس پیکربندی dual-stack رو چک کن یا دو سوکت جدا (یکی برای `0.0.0.0` و یکی برای `::`) استفاده کن.
-فرایند NAT (Network Address Translation) توی IPv4 رایجه و ممکنه باعث مشکلاتی مثل **تأخیر** یا **محدودیت در تعداد اتصالات** بشه. با IPv6 می‌تونی این محدودیت رو دور بزنی.
