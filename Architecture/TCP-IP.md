## TCP/IP چیه؟ (ساده، اما عمیق)

### یه نگاه کلی

خب **TCP/IP** اسم یه **مجموعه پروتکل** (protocol suite)ـه که اساس اینترنت و تقریباً همهٔ شبکه‌های امروزیه. دو تا پروتکل اصلیش — **TCP** و **IP** — انقدر مهم بودن که اسم کل مدل روشون موند؛ ولی TCP/IP فقط این دو تا نیست، یه **مدل لایه‌ای** هست که چندین پروتکل توی لایه‌های مختلف روش سوار میشن.

- **پروتکل IP (Internet Protocol) :** مسئول آدرس‌دهی و روتینگ بسته‌ها از مبدا به مقصد. بدون اتصال و بدون تضمین تحویل.
- **پروتکل TCP (Transmission Control Protocol) :** یکی از پروتکل‌های لایهٔ انتقال؛ روی IP سوار میشه و جریان بایت قابل اعتماد و مرتب می‌ده.
- **پروتکل  UDP (User Datagram Protocol) :** پروتکل دیگهٔ لایهٔ انتقال؛ روی IP سوار میشه و دیتاگرام سریع و بدون تضمین تحویل می‌فرسته.

پس وقتی می‌گی «TCP/IP»، منظور همون **مدل و مجموعه پروتکل‌ها**ست که توش IP نقش لایهٔ شبکه رو داره و TCP (و UDP) نقش لایهٔ انتقال رو.

این مجموعه پروتکل در دهه 1960 توط وزارت دفاع ارائه شده.

---

## مدل لایه‌ای TCP/IP 

مدل TCP/IP معمولاً با **چهار لایه** توصیف میشه (گاهی لایهٔ فیزیکی رو جدا می‌گیرن و پنج لایه می‌شن). از بالا به پایین:

| لایه                                  | مثال پروتکل‌ها                     | وظیفهٔ کلی                                                                            |
| ------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------- |
| **برنامه (Application)**              | HTTP، HTTPS، DNS، SMTP، gRPC، QUIC | پروتکل‌هایی که برنامه با اونها حرف می‌زنه مثل یک رابط کاربری بین سرویس های نرم افزاری |
| **انتقال (Transport)**                | TCP، UDP                           | مدیریت جریان داده با استفاده از پروتکل های انتقال داده                                |
| **شبکه / اینترنت (Network)**          | IP (IPv4، IPv6)، ICMP              | آدرس‌دهی و روتینگ بسته‌ها در شبکه با استفاده از IP                                    |
| **لینک / دسترسی به شبکه (Data-Link)** | Ethernet، Wi‑Fi، PPP               | فریم بندی و کنترل دسترسی رسانه به قطعات فیزیکی با استفاده از MAC                      |
| **لایه فیزیکی (Physical)**            |                                    | انواع سیم ها کابل ها WIFI و ....                                                      |


**جریان دیتا از برنامه اینطوریه:**
	1. برنامه با یک پروتکل لایهٔ Application (مثلاً HTTP) دیتا رو می‌فرسته.
	2. لایهٔ Transport (TCP یا UDP) دیتا رو با شمارهٔ پورت مبدا و مقصد داخل **segment** (TCP) یا **datagram** (UDP) می‌ذاره.
	3. لایهٔ Network آدرس (IP) اون رو داخل **پاکت IP** می‌ذاره و آدرس IP مبدا و مقصد رو می‌زنه.
	4. لایهٔ Data-Link اون رو داخل **فریم** (مثلاً Ethernet) می‌ذاره و روی رسانهٔ فیزیکی با آدرس MAC مورد نظر می‌فرسته.
	5. و لایه Physical جاده ای هست که دیتا ازش عبور میکنه.
	**نکته:** در مقصد عکس این اتفاق می‌افته: هر لایه هدر خودش رو برمی‌داره و به لایهٔ بالاتر می‌ده تا در نهایت به برنامهٔ درست (با اون پورت) برسه.

## لایه برنامه - Application Layer

اینجا یک بستری فراهم شده که برنامه های کاربردی مثل مروگرها، کلاینت های ارسال پیام و یا اشتراک گذاری فایل بتونن ازش برای ارتباط برقرار کردن و انتقال دیتا استفاده کنن.

وظایف اصلی لایهٔ برنامه عبارتند از:

1. **فرمت‌بندی و ترجمه داده (Translation)** : تبدیل داده‌های متنی (مثلاً ASCII) به باینری قابل پردازش توسط دستگاه.
2. **فشرده‌سازی (Compression)** : کاهش حجم داده‌ها با استفاده از الگوریتم‌های فشرده‌سازی مانند (Lossless یا Lossy).
3. **رمزگذاری** : محافظت از داده‌ها از طریق رمزنگاری (مثلاً TLS/SSL برای برقراری ارتباطات امن).

پروتکل های ارائه شده توسط لایه Application عبارتند از:
 1. **سیستم نامگذاری دامنه (DNS)** : این لایه به نگاشت یا اختصاص یک نام دامنه خاص به آدرس IP کمک می کنه.
 2. **پروتکل های HTTP / HTTPS** : این لایه از این پروتکل های برای مرور وب سایت ها استفاده می کنه.
 3. **پروتکل FTP** : این لایه همچنین از این پروتکل برای انتقال فایل برای اشتراک گذاری فایل ها بین دستگاه ها استفاده میکنه.
 4. **پروتکل SMTP** : این لایه همچنین از SMTP برای ارسال و دریافت ایمیل ها استفاده می کنه.

## لایه انتقال - Transport Layer

مهم ترین لایه در TCP/IP لایه انتقال هست که انتقال داده های قابل اعتماد بین دستگاها رو تضمین می کنه. این لایه نقش مهم تو مدیریت جریان داده در محیط شبکه ایفا میکنه. لایه انتقال دو پروتکل مهم رو ارائه میده :
1. **پروتکل TCP (Transmission Control Protocol)** 
2. **پروتکل UDP (User Datagram Protocol)**
---

### TCP (Transmission Control Protocol)

در اصل TCP یه پروتکل **اتصال‌گرا (Connection‑oriented)** و **قابل اعتماد** هست. یعنی قبل از ارسال داده، بین دو طرف یه اتصال مجازی برقرار می‌کنه (با سه‌مرحله دست دادن - handshake) و بعد داده رو به‌ صورت جریان بایت با ترتیب و بدون خطا تحویل می‌ده.

پروتکل TCP شامل 3 فاز هست :
	1. ایجاد اتصال (Connection establishment)
	2. انتقال داده (Data transfer)
	3. پایان اتصال (Connection Termination)

- **ایجاد اتصال (Connection establishment)** :
	برای ایجاد ارتباط بین کلاینت و سرور یا فرستنده و گیرنده سه مرحله پیش رومونه (Three-way TCP Connection handshake) : 
	    1.  کلاینت باید درخواست اتصال (Connection Request) رو به سرور ارسال کنه. 
		2.  سرور درخواست رو تایید میکنه و یک تاییدیه (Acknowledgment-client) برای کلاینت ارسال میکنه. 
		 3. وقتی تاییدیه از طرف کلایت دریافت شد یک تاییدیه (Acknowledgment-server) دیگه از طرف کالاینت به سروری که اتصال رو برقرار میکنه میفرسته.

    ![[Pasted image 20260311121731.png]]
	توضیح عکس :
	- **سه‌مرحله دست دادن (Three-way Handshake):**  
	  ۱. کلاینت (synchronize) `SYN` با seq=x می‌فرسته  
	  ۲. سرور `SYN-ACK` با seq=y و ack=x+1 می‌فرسته  
	  ۳. کلاینت `ACK` با ack=y+1 می‌فرسته  
	  بعد از این، اتصال برقرار و داده می‌تونه رد و بدل بشه.
	   این کار state ایجاد می‌کنه و سربار داره (حدود ۱.۵ RTT قبل از اولین داده).


- **انتقال داده (Data Transfer)** :
	این مرحله شامل 4 ویژگی هست :
		1. *انتقال داده های سفارشی (Ordered data transfer)*
		2. *انتقال داده بدون خطا (Error free data transfer)*
		3. *ارسال مجدد داده های از دست رفته (Retransmission of lost data)*
		4. *حذف بخش های تکراری (Discarding duplicated segments)*

	- **انتقال داده های سفارشی (Ordered data transfer)** :
		لایه Transfer داده ها را به چند بخش واحد (Data Unit) تقسیم می کنه که به اون دیتا سگمنت Data segment میگن. به هر دیتا سگمنت یک شماره دنباله (sequence number) و شماره پورت (Port Number) اضافه میشه. شماره پورت مشخص میکنه داده باید به کدوم پورت در گیرنده بره و شماره دنباله برای مرتب کردن مجدد سگمنت ها به داده های کامل در گیرنده استفاده میشه.
		شماره دنباله تضمین میکنه که داد ها به شیوه ای منظم منتقل میشن.
		
	- **انتقال داده بدون خطا (Error free data transfer) :**
		لایه Transfer به هر واحد داده که از کلایت به سرور منتقل میشه یک CHECKSUM اختصاص داده میشه  که یکپارچگی (Integrity) داده ها رو تضمین میکنه. اگر داده ها دستگاری بشن CHECKSUM تغییر میکنه و گیرنده این رو میدونه و اون هارو دور میریزه و به فرستنده تاییدیه (Ack) ارسال نمیکنه پس گیرنده اگر تا زمان معینی تاییدیه نگیره واحد داده رو مجدد ارسال میکنه حالا اگر CHECKSUM درست باشه گرینده تاییدیه رو به سمت مشتری ارسال میکنه.
		
	- **ارسال مجدد داده های از دست رفته (Retransmission of lost data) :**
		فرض کنید فرستنده واحد داده رو به گیرنده ارسال میکنه و در حین انتقال داده به هر دلیلی از بین میره. حالا گیرنده اصلا واحد داده ای دریافت نکرده و تاییدیه ای هم سمت فرستنده ارسال نشده حالا فرستنده کمی منتظر میمونه و دوباره واحد داده رو ارسال میکنه، اگر واحد داده به گیرنده برسه و تاییدیه ای صادر بشه و به فرستنده برسه، فرستنده از ارسال مجدد اون واحد داده دست میکشه.
		
		![[Pasted image 20260312051014.png]]
		
	- **حذف بخش های تکراری (Discarding duplicated segments) :**
		فرض کنید فرستنده یک واحد داده به سمت گیرنده ارسال میکنه و همزمان گیرنده در حال پردازش درخواست های دیگه هست و ارسال تاییدیه مدتی طول میکشه تو این مدت فرستنده فکر میکنه بسته از بین رفته درصورتی که واحد داده به درستی به گیرنده رسیده ولی فرستنده دوباره واحد داده رو به گیرنده ارسال میکنه. تو این شرایط گیرنده میتونه بسته جدید تکراری رو در نظر نگیره.

- **پایان اتصال (Connection Termination)** :
	تو این مرحله فرستنده یک سیگنال اتمام اتصال به سمت گیرنده ارسال میکنه و گیرنده تاییدیه قطع ارتباط رو به فرستنده ارسال میکنه و مجدد گیرنده سیگنال اتمام اتصال رو به فرستنده ارسال میکنه و حالا فرستنده تاییدیه رو به سمت گیرنده ارسال میکنه. تو این شرایط 4 درخواست رد و بدل شده که به اون Four-Way handshake گفته میشه.
	
	![[Pasted image 20260312051936.png]]
	توضیح عکس:
	 - **پایان اتصال (Four-way Handshake):**  
		۱. کلاینت `FIN` می‌فرسته (دیگه داده‌ای ندارم)  
	  ۲. سرور `ACK` می‌ده  
	  ۳. سرور `FIN` می‌فرسته (منم تموم کردم)  
	  ۴. کلاینت `ACK` می‌ده و بعد از مدتی (TIME_WAIT) اتصال رو می‌بنده.


- برخی از ویژگی های دیگه ای TCP که میتونین مطالعه بیشتری روش داشته باشین :
	1. **کنترل جریان (Flow Control):** با استفاده از **پنجره دریافت (Receive Window)**، گیرنده به فرستنده می‌گه چقدر جا داره. این کار از غرق شدن گیرنده جلوگیری می‌کنه.
	2. **کنترل ازدحام (Congestion Control):** TCP سعی می‌کنه شبکه رو بیش از حد شلوغ نکنه. الگوریتم‌هایی مثل **Slow Start**, **Congestion Avoidance**, **Fast Retransmit** و **Fast Recovery** این کار رو انجام می‌دن. معروف‌ترین پیاده‌سازی‌ها: Reno, CUBIC, BBR.

### UDP (User Datagram Protocol)

در اصل UDP یک پروتکل **بدون اتصال (Connectionless)** و **غیر قابل اعتماد** هست. همچنین ترتیب داده ها و رسیدن داده و تکرار داده هم تضمین نمیشه. معمولا از این پروتکل در پلتفرم های پخش ویدیو و موزیک و بازی استفاده میشه.
در این پروتکل داده ها به واحد های کوچکتری به نام دیتاگرام (Datagram) تقسیم میشن و به گیرنده ارسال میشن. هر دیتاگرام شامل شماره پورتی هست که در فرستنده تحویل گرفته میشه.
پروتکل UDP نسبت به TCP خیلی سریع تر هست.
#### ویژگی‌های کلیدی UDP

- **سبک و سریع:** سربار خیلی کم، مناسب برای کاربردهایی که سرعت از دقت مهم‌تره (مثل بازی، VoIP، استریم ویدیو).
- **پشتیبانی از چندپخشی (Multicast):** به‌راحتی می‌تونه یک دیتاگرام رو به چندین مقصد بفرسته (کاربردهایی مثل کشف سرویس با mDNS).
- **بدون حالت:** نیازی به نگه‌داشتن state روی سرور نیست، بنابراین مقیاس‌پذیری بالایی داره.
- **کوله‌بار (Overhead) کم:** هدر UDP فقط ۸ بایت (در مقابل ۲۰ بایت برای TCP بدون آپشن).

#### کاربردهای رایج UDP

- **در DNS:** پرس‌وجوهای DNS معمولاً با UDP میرن (اگه طولانی باشه، fallback به TCP).
- **در DHCP:** تخصیص IP با UDP.
- **در VoIP (مثلاً SIP/RTP):** تأخیر کم مهم‌تر از خطاست.
- **بازی‌های آنلاین:** وضعیت بازی هر لحظه ارسال می‌شه؛ از دست رفتن یه بسته شاید قابل چشم‌پوشی باشه.
- **در QUIC (پروتکل لایهٔ انتقال، RFC 9000):** روی UDP سوار می‌شه و قابلیت‌های TCP رو به‌صورت کارآمدتری ارائه می‌ده (پایهٔ HTTP/3).
- **سیستم‌های مانیتورینگ و logging:** مثل statsd که جمع‌آوری متریک رو با UDP انجام می‌ده.

#### تصمیم‌گیری: TCP یا UDP؟

| نیازمندی | پیشنهاد | مثال |
|----------|----------|------|
| دقت کامل، ترتیب، تحویل‌دهی تضمینی | TCP | HTTP/1, HTTP/2, پایگاه داده، ایمیل |
| تأخیر کم، از دست رفتن قابل تحمل | UDP | بازی، VoIP، DNS, QUIC |
| پخش همگانی یا گروهی (multicast) | UDP | کشف سرویس در شبکه |
| اتصال‌های طولانی با بسته‌های کوچک | TCP (با keep-alive) | WebSocket, MQTT |
| امنیت و رمزنگاری | TLS روی TCP | HTTPS |
| سرعت بالا و کاهش سربار handshake | QUIC (روی UDP) | HTTP/3 |

## لایه شبکه - Network layer

لایه شبکه برای انتقال داده ها از یک دستگاه به دستگاه موجود دیگه تو یک شبکه دیگه کاربرد داره.
دیتاگرام های UDP یا دیتا سگمنت های TCP از لایه Transport را در این لایه دریافت میکنیم. که از اونها برای ایجاد یک Packet در لایه شبکه استفاده میکنیم. این لایه مسئول آدرس دهی منطقی و همچنین مسیریابی (Logical Addressing and Routing) هست.
**پس شامل 3 ویژگی هست:**
	  **بسته‌بندی:** 
	  دیتای لایهٔ بالاتر (مثلاً یک segment TCP) داخل **پاکت IP** (IP packet) قرار می‌گیره؛ به این پاکت معمولاً **دیتاگرام IP** هم می‌گن. 
	**آدرس دهی :**  
	هر دستگاه روی شبکه یه آدرس IP داره (مثلاً `192.168.1.1` در IPv4 یا `2001:db8::1` در IPv6). در لایه شبکه دیتا سگمنت یا دیتاگرام از لایه انتقال گرفته میشود و IP مبدا و مقصد به اون اضافه میشه. که از IP برای تحویل داده ها به دستگاه خاصی از طریق شبکه استفاده میشه.
	**مسیریابی Routing :** 
	روترها با نگاه کردن به آدرس مقصد، بسته رو به «لینک بعدی» (next hop) می‌فرستن تا به مقصد برسه. پس روتینگ چیزی نیست جز تعیین کوتاه ترین مسیر ممکن که میتوان از مبدا به مقصد رسید.

### یه نگاه به (IP)؛ قلب مسیریابی

- **آدرس‌دهی:** هر دستگاه روی شبکه یه آدرس IP داره (مثلاً `192.168.1.1` در IPv4 یا `2001:db8::1` در IPv6).
- **روتینگ:** روترها با نگاه کردن به آدرس مقصد، بسته رو به «لینک بعدی» (next hop) می‌فرستن تا به مقصد برسه.
- **بسته‌بندی:** دیتای لایهٔ بالاتر (مثلاً یک segment TCP) داخل **پاکت IP** (IP packet) قرار می‌گیره؛ به این پاکت معمولاً **دیتاگرام IP** هم می‌گن.

## لایه پیوند داده - Data-Link layer

این لایه مسئول انتقال داده ها در یک شبکه فیزیکی هست. دوتا لایه فرعی (Sub-Layers) برای این لایه وجود دارن:
	1.کنترل پیوند منطقی (Logical Link Control-LLC)
	2.کنترل دسترسی رسانه (Media Access Control-MAC)
بسته داده (Data Packet) ای که از لایه شبکه وارد این لایه میشود شامل آدرس IP مبدا و مقصد هست. در این لایه آدرس فیزیکی (MAC) دستگاه مبدا و دستگاه مقصد رو به بسته داده اضافه میشه و یک Ethernet Frame ایجاد میشه.
آدرس MAC توسط کارت شبکه موجود به صورت منحصر به فرد به هر دستگاه از سمت کارخانه داده میشه.
در اصل MAC یک عدد هگزادسیمال 12 رقمی منحصر به فرده که دستگاه متصل به شبکه رو مشخص میکنه.

## از دید توسعهٔ بک‌اند

وقتی یه سرویس وب یا API می‌نویسی:

- **لایهٔ برنامه:** مثلاً HTTP؛ درخواست و پاسخ رو با روش و مسیر و هدر و بدنه تعریف می‌کنی.
- **لایهٔ انتقال:** فریمورک (مثلاً Kestrel در ASP.NET Core) روی TCP گوش می‌ده؛ پورت (مثلاً ۴۴۳) مشخص می‌کنه این سرویس کدوم برنامه روی این ماشینه.
- **لایهٔ شبکه:** IP آدرس ماشین رو مشخص می‌کنه؛ روترها بسته‌ها رو با همین آدرس‌ها مسیریابی می‌کنن.
- **لایهٔ لینک:** کارت شبکه و درایور و سوئیچ/روتر محلی؛ معمولاً مستقیم بااش کار نمی‌کنی.

مفاهیمی که زیاد بهشون برمی‌خوری:

- **آدرس IP و پورت:** ترکیب `IP:Port` یک **endpoint** رو تعریف می‌کنه (مثلاً `192.168.1.10:443`).
- **فایروال و NAT:** روی همین لایه‌ها کار می‌کنن؛ باز/بسته بودن پورت و مسیر ترافیک رو با IP و پورت (و گاهی پروتکل) تعیین می‌کنن.
- **آدرس localhost و 127.0.0.1:** آدرس loopback؛ ترافیک از همون ماشین رد میشه و به شبکهٔ فیزیکی نمی‌ره.

### نکات عیب‌یابی و ابزارها

- **netstat** یا **ss:** ببین چه پورت‌هایی روی سیستم بازه و چه اتصالاتی برقراره.
- **tcpdump / wireshark:** بسته‌ها رو ضبط و تحلیل کن.
- **ping:** بررسی لایه شبکه با ICMP.
- **traceroute:** مسیری که بسته‌ها میرن رو ببین.
- **telnet / nc (netcat):** تست دستی یه پورت خاص.

## مفاهیم پیشرفته و آینده

- **مفهوم Multipath TCP (MPTCP):** یه اتصال TCP رو روی چند مسیر مختلف می‌فرسته (مثلاً وای‌فای و ۴G همزمان). توی iOS ازش استفاده می‌شه.
- **مفهوم TCP BBR:** الگوریتم کنترل ازدحام که گوگل ساخته؛ به‌ویژه برای شبکه‌های با نرخ بسته‌گم‌شدگی بالا (مثل شبکه‌های موبایل) بهره‌وری بهتری داره.
- **مفهوم QUIC (Quick UDP Internet Connections):** پروتکل لایهٔ انتقال (استاندارد IETF، RFC 9000؛ نخست توسط گوگل طراحی شد) که روی UDP سوار می‌شه، handshake سریع‌تر، multiplexing بدون blocking، و امنیت داخلی (TLS) داره. پایهٔ HTTP/3.
- **مفهوم HTTP/3:** روی QUIC اجرا می‌شه و مشکلات Head-of-Line blocking توی HTTP/2 رو حل می‌کنه.
