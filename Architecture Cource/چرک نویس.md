# Software Architecture
معماری نرم افزار رو اینطوری میشه تعبیر کرد که یک طرح اولیه هست برای سیستم های نرم افزاری به این صورت که در این طرح ما اطلاعات شامل مولفه های نرم افزار (components) نحوه تعامل این مولفه ها با یکدیگر و معماری انهاست.
- Software Architecture as a blueprint for software systems
- Defines overall structure and high-level design
- Organizes system components and their interactions
مفاهیم کلیدی وجود دارند که میتونیم به نگاه سطح بالا از مولفه های سیستم اشاره کنیم به معنی اینکه یکسری مولفه مستقل در سیستم پیدا کنیم مثل سیستم تجارت الکترونیکی که خدمات مشتریان، انبارداری، سیستم خرید جزوی از مولفه های این سیستم هستند.
که البته ارتباط بین اینها مهم هستن اینکه چطور بهم سرویس میدهند و تعامل میکنن.
که موارد بالا جزو معماری نرم افزار هستن.
- Key concepts
	- components: Independent parts of the sytem
		- High level components: For example, user service, purchase service, inventory service
		
	- Connectors: Communication paths like APIs, Messaging system or databases

یک معماری نرم افزار همچنین درمورد الگو ها و سبک های طراحی تصمیم گیری میکنه مثلا از الگوی MVC استفاده کنیم یا کل سیستم رو مایکروسرویس بکنیم.
- Practical Use Case : E-Commerce Platform
- Architecture and Design Patterns

# Software Architecture vs System Design 

معماری نرم افزار به معنی دید سطح بالا و طراحی ساختار کلی هست.
طراحی نرم افزار به معنی اجرای دقیق جزئیات معماری هست.
**مثال** : در پروژه تجارت الکترونیک به طور فرضی اگر از یک معماری کلی مایکروسرویس استفاده کنیم زبان پیاده سازی مولفه ها و تکنولوژی های مورد استفاده داخل اون ها میشه که جزئیات بخشی از طراحی سیستم هست.

 Software Architecture Roles and Responsibility Comparison
- Architecture
	- **Software Architecture** : 
		- Defines overall structure and high-level design.
	- **System Design** :  
		- Fucoses on detailed implementation.

در سطح مولفه میتونیم بگیم که معماری نرم افزار درمورد مولفه های اصلی که باید وجود داشته باشن و مسئولیت مولفه ها صحبت میکنیم.
اما در طراحی سیستم ما درمورد جزئیاتی مثل انتخاب دیتابیس، زبان برنامه نویسی و... صحبت میکنیم.
- Components 
	- **Software Architecture**
		- Identifies major components and their responsibility.
	- **System design**
		- Details implementations, include internal logic, data storage, and component interaction.

در سطح مدل داده میشه گفت معماری نرم افزار ساختار داده های کلی و ساختار انها هست.
ولی در طراحی نرم افزار مدل ها و ارتباطات بینشون و اسکیما ها طراحی و بحث میشوند.
- Data Models 
	- **Software Architecture**
		- Defines overall data architecture and data organization across the system. 
	- **System design**
		- Details implementations, include internal logic, data storage, and component interaction.

در سطح زیر ساختی معماری درمورد استراتژی های استقرار و چگونگیشون صحبت میکنه.
و طراحی نرم افزار به نحوه تنظیم و اجرا و لود بالانسینگ و ... میپردازه.

- Infrastructure 
	- **Software Architecture**
		- Defines overall infrastructure and high-level deployment strategy. 
	- **System design**
		- Specifies detailed infrastructure setup, server configuration and load balancing.

# Software Architect Roles
معمار نرم افزار میگوید که چطور میتونیم یک سیستم رو سازمان دهی کنیم. چه مولفه هایی را در اختیار خواهیم داشت و چطوری در راستای رسیدن به هدف سیستم مولفه ها باهم کار میکنند.
معماران بیشتر بر ایجاد یک طرح که تیم توسعه رو در ساخت یک سیستم راهنمایی میکنه تمرکز دارن.
انها سیسیتم های مقیاس پذیر و قابل نگهداری و نیاز های عملکردی (Functional) یا غیر عملکردی (Non-Functional) رو براورده میکنن.
معمار نرم افزار درمورد ساختار کلی همچنین استفاده از مایکروسرویس یا مونولیت یا معماری های سرویس گرا و نحوه تعامل اجزا میگیرد تصمیم میگیرند.
انتخاب ابزار ها و تکنولوژی متناسب با پروژه همچنین به دست معمار انجام میشود.
همچنین ایجاد مستندات مفصل که به برنامه نویس کمک میکند چطور سیستم رو پیاده سازی و ارتباط مولفه ها را اعمال کند از کار های معمار نرم افزار هست.
همچنین رهبری و دستور العمل های فنی برای اطمنیان از ساخت سیستم هم جزو وظایف اون هست.

- Role : 
	- designing the technical of the system 
	- Focus: Creating a scalable, maintainable blueprint
- Key responsibility:
	- defining the software structure -> decide architecture
	- Choosing technologies -> select tools and frameworks
	- Create documentation -> provide architecture diagram


# Solutions Architect Roles

معمار راه حل در اصل راه حل های فنی و فناوری طرح بالایی ارائه میدهد تا یک مشکل تجاری رو حل کنه.
تمرکز روی این هست که چگونه فناوری های مختلف به منظور ارائه سیستمی که مطابق نیاز های تجازی هست ادغام شود.


 - Role :
	 - Designing technology solutions
	 - Fucoses on integrating systems and technologies to solve
	 - Business problems

معمار راه حل با ذینفعان و تیم اجرایی برخورد داره و نیاز های بیزنس رو برای رسیدن به اهداف و رفع چالش ها بررسی میکنه.
انتخاب سیستم عامل ها فناوری ها یا خدماتی که کمک به حل مسائل میکنه را ارائه میده.
- Understanding business needs
	- Engage with stakeholders: Understanding business goals and challenges
- Designing end-to-end solutions
	- Comprehensive design: Integrate multiple systems and technologies
- Selecting technologies
	- choose appropriate technologies : Select platforms and services that fit the solution
- Ensuring alignment with enterprise architecture
	- Fit within enterprise IT strategy : Ensure solutions align with broader architecture and standards
- Overseeing implementation
	- Guide implementation : Work with technical teams to ensure solutions are properly implemented.
# Solution Architect vs Software Architect
تمرکز معمار راه حل روی فناوری و نیاز های بیزنس هست درصورتی که معمار نرم افزار سرویس های مشخص شده توسط معمار ره حل را طراحی و دیزاین میکند و عملا با مشتری و ذینفعان وارد مباحثه نمیشود و صرفا با برنامه نویس ها درگیر بررسی پیاده سازی درست مولفه ها هست.
معمار راه حل مشخص میکند که چگونه یک سیستم داخلی موجود با نیاز هایی جدید کاربر ادغام شود تا یکپارچگی سیستم مشخص شود.
در نهایت معمار راه حل یک ناظر بین مشتری و برنامه نویس ها تا نیاز هارو به درستی پیگیری و رفع کند.
# Architectural Vision
معمار سیستم باید سیستم را به عنوان یک کل در نظر بگیرد نه فقط مجموعه ای از قطعات جداگانه.
معمار متوجه هست که چگونه مولفه ها در Big Picture متناسب هستن و یک تغییر چه تاثیراتی رو کل سیستم ها دارد.
اون لایه های معماری را میشناسد و روی موارد امنیتی و نگهداری و سادگی پروژه تمرکز دارد همچنین به Trad-offs توجه میکند.
تفکر معمار به صورتی هست که فقط به نیاز های امروز توجه نمیکنه و آینده نگری داره.

- **Holistic view**
	- Understanding the system as a whole 
	- Visualizing system layers and data flow
- **Focus on non-functional requirements**
	- Ensuring scalability, performance, and security
	- Designing for high availability and redundancy 
- **Balancing Trade-Offs**
	- Weighing competing priorities
	- Focusing on maintainability and simplicity
- **Future-Proofing**
	- Building systems adaptable to future needs
	- Designing for scalability and flexibility

# Key aspects of architectural vision

- Alignment with business goals
	- Bridging gap between technical and business objective
	- Supporting rapid time-to-market and customization
- Simplicity and elegance
	- Striving for efficient and understandable designs  
	- Avoid unnecessary complexity
- Continuous learning and adaptation
	- Keeping up with evolving technology
	- leveraging the latest tools and frameworks
- Risk Management
	- Identifying and mitigating potential risks
	- Addressing integration and technical debt challenges
