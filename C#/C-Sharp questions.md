# سوالات متداول مصاحبهٔ C#

## 1. Interview Relevance Summary

این فایل **سوال‑پاسخ‌های کوتاه** مباحث پایهٔ C# را برای مصاحبهٔ Backend جمع می‌کند. مصاحبه‌گران انتظار دارند بتوانی هر مفهوم را در یک یا دو جمله درست توضیح دهی و **تفاوت**ها و **زمان استفاده** را بگویی. در سطح Senior علاوه بر تعریف، **trade-off** و **اشتباه رایج** را هم باید بدانی. برای توضیح عمیق‌تر هر موضوع به فایل مربوط در همین پوشه (مثلاً OOP، ValueType و ReferenceType، DbContext) مراجعه کن.

---

## 2. سوالات و پاسخ‌ها

### ۱. سی‌شارپ چیست؟

یک **زبان برنامه‌نویسی** در اکوسیستم **.NET** با سینتکس شبیه C++. ویژگی‌های مهم: **سرعت توسعه** (امکانات زبانی و ابزار) و **قدرت** (نوع‌امن، شیءگرا، قابل تعامل با پلتفرم). کد به **IL** کامپایل می‌شود و توسط **CLR** اجرا می‌شود. از ابتدا **شیءگرا** است (کلاس، interface، ارث‌بری).

### ۲. اصول شیءگرایی چیست؟

چهار اصل معمول:

- **Abstraction (انتزاع)**: جدا کردن «چه می‌خواهیم» از «چطور پیاده شده»؛ با abstract class و interface.
- **Encapsulation (کپسوله‌سازی)**: پنهان کردن پیاده‌سازی و محدود کردن دسترسی با **Access Modifier** (private, protected, public و غیره).
- **Inheritance (ارث‌بری)**: کلاس فرزند از کلاس والد ویژگی‌ها و رفتار را به ارث می‌برد و می‌تواند گسترش دهد.
- **Polymorphism (چندریختی)**: یک «نوع» یا «متد» در ظاهر یکسان، با رفتارهای مختلف — مثلاً **Overloading** (همنام با پارامترهای متفاوت) یا **Override** (بازنویسی متد virtual در فرزند).

### ۳. آبجکت چیست؟

**نمونه (instance)** از یک **کلاس**. کلاس فقط قالب است؛ با `new` (یا برای struct بدون new در بعضی موارد) یک **بلوک حافظه** به شکل آن قالب ساخته می‌شود که همان آبجکت است. می‌توانی چندین instance از یک کلاس داشته باشی.

### ۴. Managed و Unmanaged چیست؟

- **Managed**: کد نوشته‌شده با .NET به **IL** کامپایل می‌شود و توسط **Runtime (CLR)** اجرا می‌شود. مدیریت حافظه (GC)، نوع‌امنی و سرویس‌های runtime در اختیار تو است.
- **Unmanaged**: کدی که مستقیم به **زبان ماشین** (یا مثلاً از طریق C++) کامپایل می‌شود و به‌صورت DLL یا native در پروژه استفاده می‌شود؛ خارج از مدیریت مستقیم CLR (مثلاً حافظه را خودت مدیریت می‌کنی یا از کتابخانهٔ native استفاده می‌کنی).

### ۵. Boxing و Unboxing چیست؟

- **Boxing**: تبدیل یک **Value Type** به **Reference Type** (مثلاً `int` به `object`). مقدار روی **Heap** کپی می‌شود و یک reference به آن ساخته می‌شود؛ هزینه دارد.
- **Unboxing**: برعکس — از reference به Value Type برگرداندن مقدار به stack (یا به متغیر value type). اگر نوع با نوع boxing‌شده یکی نباشد، exception رخ می‌دهد.

### ۶. تفاوت struct و class؟

| موضوع | struct | class |
|--------|--------|--------|
| نوع | Value Type (از ValueType) | Reference Type (از Object) |
| مکان حافظه | معمولاً Stack (یا داخل آبجکت) | Heap |
| ارث‌بری | فقط از interface؛ نه از کلاس | از یک کلاس و چند interface |
| Abstract | ندارد | می‌تواند abstract باشد |
| Constructor | دارد (با محدودیت؛ همهٔ فیلدها باید مقدار بگیرند)؛ از C# 10 parameterless هم مجاز است | دارد |
| new | برای struct الزامی نیست (مقادیر پیش‌فرض)؛ با new هم می‌شود | برای ساخت instance معمولاً لازم است |

کاربرد struct برای **دادهٔ کوچک و سبک** که کپی‌شدن ارزان است؛ class برای موجودیت‌های بزرگ‌تر و وقتی هویت (reference) مهم است.

### ۷. تفاوت Interface با Abstract Class؟

| موضوع | Abstract Class | Interface |
|--------|-----------------|-----------|
| ارث‌بری | فقط **یک** abstract class | **چند** interface |
| پیاده‌سازی متد | می‌تواند متد با بدنه داشته باشد | تا C# 7 فقط امضای متد؛ از C# 8 **Default Implementation** مجاز است |
| فیلد / متغیر | می‌تواند داشته باشد | نه (فقط پراپرتی با امضا یا با default impl) |
| Constructor | دارد | ندارد |
| Access Modifier | برای اعضا می‌توان private, protected, public گذاشت | اعضای interface به‌صورت public هستند (قابل تغییر با C# 8) |

هر دو برای **انتزاع** و قرارداد استفاده می‌شوند؛ abstract وقتی یک پایهٔ مشترک با منطق مشترک داری؛ interface وقتی فقط «قرارداد» بدون سلسله‌مراتب واحد می‌خواهی.

### ۸. Enum چیست؟

نوعی برای **ثابت‌های نام‌دار** (مثلاً وضعیت‌ها یا گزینه‌های شمارشی). به هر عضو یک مقدار عددی (پیش‌فرض int) نسبت داده می‌شود. **ثابت** و قابل استفاده در switch و مقایسه؛ برای خوانایی کد و جلوگیری از «عدد جادویی». از نظر ذخیره‌سازی به‌صورت value type است (معمولاً در stack یا داخل ساختار).

### ۹. Continue و Break چه تفاوتی دارند؟

- **break**: خروج از **حلقه** (یا switch)؛ اجرا بعد از بلوک ادامه می‌یابد.
- **continue**: **رد کردن** همان دور از حلقه و رفتن به دور بعد؛ حلقه تمام نمی‌شود.

### ۱۰. readonly و const چه تفاوتی دارند؟

- **const**: در **زمان کامپایل** مقدارش مشخص است؛ باید هنگام تعریف مقداردهی شود؛ در همهٔ instanceها و حتی بدون instance یکسان است؛ در metadata اسمبلی ذخیره می‌شود.
- **readonly**: مقدارش می‌تواند در **Constructor** یا هنگام تعریف داده شود؛ **runtime** است؛ برای هر instance می‌تواند متفاوت باشد (اگر در constructor مقدار بگیرد). بعد از ساخت شیء دیگر قابل تغییر نیست.

### ۱۱. تفاوت ref و out؟

هر دو برای **pass by reference** هستند (تغییر در متد روی همان متغیر فراخوان‌کننده اثر می‌گذارد).

- **ref**: متغیر باید **قبل از فراخوانی مقداردهی** شده باشد؛ متد می‌تواند بخواند و بنویسد.
- **out**: متد **حتماً** باید مقدار بدهد؛ فراخوان‌کننده نیازی به مقداردهی اولیه ندارد. برای خروجی‌های چندگانه یا وقتی «بازگشت موفق/ناموفق + مقدار» می‌خواهی استفاده می‌شود.

**نکته**: پراپرتی را نمی‌توان با ref یا out ارسال کرد؛ فقط متغیر محلی یا فیلد در متد.

### ۱۲. this چیست و آیا در متد static می‌توان از آن استفاده کرد؟

**this** اشاره به **نمونهٔ جاری** کلاس است. در متد **instance** برای دسترسی به فیلدها و متدهای همان نمونه به‌کار می‌رود. متدهای **static** به نمونه تعلق ندارند؛ پس داخل آن‌ها **this** معنا ندارد و استفاده از this خطا است.

### ۱۳. پراپرتی (Property) چیست؟

مکانیزمی برای **خواندن و نوشتن** یک مقدار (معمولاً با یک فیلد پشتیبان) با سینتکس ساده. **get** و **set** می‌توانند دسترسی جدا داشته باشند (مثلاً فقط get عمومی، set خصوصی). کلمهٔ **value** در set به مقدار ورودی اشاره می‌کند. پراپرتی **پل** بین دنیای بیرون و متغیر داخلی است و می‌تواند اعتبارسنجی یا منطق ساده در get/set داشته باشد.

### ۱۴. Extension Method چیست و چطور ساخته می‌شود؟

متدی که **روی نوعی که مالک آن نیستی** (مثلاً string یا نوع کتابخانه) فراخوانی می‌شود، گویی عضو همان نوع است. در یک **کلاس static** به‌صورت **متد static** تعریف می‌شود؛ پارامتر اول با **this** نوعی که می‌خواهی extend کنی است (مثلاً `this string s`). مثال: `"text".MyExtension()`.

### ۱۵. string و StringBuilder چه تفاوتی دارند؟

- **string**: **غیرقابل تغییر (immutable)** است. هر «تغییر» در واقع یک **رشتهٔ جدید** می‌سازد و قبلی در حافظه می‌ماند تا GC جمع کند. برای تعداد زیاد concatenation یا تغییر مکرر از نظر حافظه و سرعت بهینه نیست.
- **StringBuilder**: **قابل تغییر (mutable)** است؛ در یک بافر درون‌حافظه تغییر می‌کند و در نهایت می‌توانی با `ToString()` یک string بگیرید. برای ساخت رشته با تغییرات زیاد مناسب است.

### ۱۶. Delegate چیست و چه کاربردی دارد؟

**Delegate** نوعی است که به **متد** اشاره می‌کند (مثل اشاره‌گر به تابع). یک نمونهٔ delegate می‌تواند به یک یا چند متد اشاره داشته باشد (**Invocation List**) و با `+=` و `-=` متد اضافه یا کم می‌شود. برای **رویدادها (Event)**، callback و الگوهایی مثل observer به‌کار می‌رود (مثلاً کلیک دکمه).

### ۱۷. کلاس sealed چیست؟

کلاسی که **نمی‌توان از آن ارث‌بری کرد**. برای جلوگیری از گسترش ناخواسته و روشن کردن اینکه این نوع «نهایی» است استفاده می‌شود.

### ۱۸. کلاس Partial چیست؟

اجازه می‌دهد تعریف **یک کلاس** در **چند فایل** پخش شود. در **زمان کامپایل** همهٔ بخش‌ها با هم ادغام می‌شوند و یک کلاس واحد ساخته می‌شود. برای سازماندهی فایل‌های بزرگ یا جدا کردن کد تولیدشده (مثل Designer) از کد دستی مفید است.

### ۱۹. IEnumerable چیست؟

**اینترفیس پایه** برای مجموعه‌هایی که می‌توان روی آن‌ها **تکرار (iterate)** کرد. متد **GetEnumerator** برمی‌گرداند که با آن می‌توان با **foreach** یا **LINQ** کار کرد. بسیاری از مجموعه‌های .NET (مثل List، Array) آن را پیاده‌سازی می‌کنند.

### ۲۰. Late Binding و Early Binding چیست؟

- **Early Binding**: در **زمان کامپایل** نوع و متد مشخص است (مثلاً **Overloading** — انتخاب متد بر اساس نوع و تعداد آرگومان در کامپایل).
- **Late Binding**: در **زمان اجرا** تصمیم گرفته می‌شود کدام متد فراخوانی شود (مثلاً متد **virtual** که در کلاس فرزند **Override** شده و با نوع واقعی شیء در runtime فراخوانی می‌شود).

### ۲۱. تفاوت IQueryable و IEnumerable؟

- **IEnumerable**: برای تکرار روی دادهٔ **درون‌حافظه (in-memory)**. وقتی از LINQ روی آن استفاده می‌کنی، متدهای LINQ به Objects روی همان داده در حافظه اجرا می‌شوند و همهٔ دادهٔ منبع در حافظه است.
- **IQueryable**: برای داده‌ای که معمولاً **خارج از حافظه** است (مثلاً دیتابیس). عبارت‌ها به **Expression Tree** تبدیل می‌شوند و به **Provider** (مثلاً EF) داده می‌شوند تا به کوئری (مثلاً SQL) ترجمه شوند. پس **اجرا تا وقتی که تکرار نشود به تأخیر می‌افتد** و فقط همان چیزی که لازم است از منبع بیرون کشیده می‌شود.

**نکته**: IQueryable برای **Deferred Execution** و **کاهش بار روی منبع** (مثلاً دیتابیس) است؛ با «Lazy Loading» در EF (بارگذاری Navigationها) اشتباه گرفته نشود.

### ۲۲. آرایه، List و ArrayList چه تفاوتی دارند؟

- **Array**: **طول ثابت**؛ سریع و کم‌حجم؛ نوع یکسان؛ برای محاسبات عددی و وقتی اندازه از قبل مشخص است مناسب است.
- **ArrayList**: **قابل رشد**؛ عناصر از نوع **Object**؛ boxing/unboxing برای نوع‌های value؛ یک‌بعدی. قدیمی است؛ معمولاً به **List\<T\>** ترجیح داده می‌شود.
- **List\<T\>**: **generic**؛ نوع‌امن؛ قابل رشد؛ برای بیشتر سناریوهای روزمره جایگزین ArrayList است.

### ۲۳. == با Equals چه تفاوتی دارند؟

برای **Reference Type**: **==** به‌طور پیش‌فرض **مرجع** را مقایسه می‌کند (آیا هر دو به همان شیء اشاره می‌کنند). **Equals** می‌تواند override شود تا **محتوا** را مقایسه کند (مثلاً string). برای **Value Type**: هر دو معمولاً **مقدار** را مقایسه می‌کنند مگر overload شده باشند. پس همیشه به نوع و overrideها بستگی دارد.

### ۲۴. تفاوت is و as؟

- **is**: بررسی می‌کند آیا شیء از یک نوع مشخص است (یا با الگوی جدید از C# 7 می‌توان نوع را استخراج کرد). خروجی **bool** است.
- **as**: **تبدیل نوع** به‌صورت امن؛ اگر تبدیل ممکن باشد شیء را برمی‌گرداند، وگرنه **null**. برای reference type به‌کار می‌رود.

### ۲۵. روش‌های مختلف Overloading یک متد چیست؟

**Overloading** یعنی چند متد با **همان نام** ولی **امضای متفاوت** (تعداد یا نوع یا ترتیب پارامترها). در **زمان کامپایل** بر اساس آرگومان‌های فراخوانی، متد مناسب انتخاب می‌شود. روش‌ها: تفاوت در **تعداد** پارامترها، **نوع** پارامترها، **ترتیب** پارامترها. نوع بازگشتی به‌تنهایی برای تمایز کافی نیست.

### ۲۶. جنریک (Generic) در C# چه معنایی دارد؟

امکان نوشتن **یک پیاده‌سازی** برای **انواع مختلف** بدون تکرار کد یا از دست دادن نوع‌امنی. کلاس یا متد با **پارامتر نوع** (مثلاً `List<T>`) تعریف می‌شود و در استفاده نوع واقعی (مثلاً `List<int>`) جایگزین می‌شود. کد یکسان، نوع‌امن و بدون boxing برای value type.

## 3. Key Interview Talking Points

- **OOP**: چهار اصل انتزاع، کپسوله‌سازی، ارث‌بری، چندریختی — و تفاوت Overloading (compile-time) با Override (runtime).
- **Value vs Reference**: struct و نوع‌های value در stack یا داخل شیء؛ class روی heap؛ Boxing/Unboxing هزینه دارد.
- **Abstract vs Interface**: یکی ارث‌بری، پیاده‌سازی و فیلد و constructor؛ دیگری چند interface، بدون فیلد و بدون constructor.
- **ref و out**: هر دو by reference؛ out نیاز به مقداردهی قبلی ندارد و متد باید حتماً مقدار بدهد.
- **string immutable، StringBuilder mutable** — برای تغییرات زیاد از StringBuilder استفاده کن.
- **IQueryable**: Expression به Provider (مثلاً EF)؛ اجرا تأخیری و کوئری روی منبع؛ **IEnumerable**: روی دادهٔ درون‌حافظه.
- **==** در reference type پیش‌فرض مقایسهٔ مرجع؛ **Equals** قابل override برای مقایسهٔ محتوا.

## 4. Common Mistakes & Red Flags

- گفتن «struct کانستراکتور ندارد» — struct می‌تواند constructor داشته باشد (با قید مقداردهی فیلدها).
- خلط **IQueryable** با **Lazy Loading** در EF — اولی دربارهٔ تأخیر در اجرای کوئری و ترجمه به SQL است؛ دومی دربارهٔ بارگذاری Navigationها.
- گفتن همیشه «== مرجع و Equals مقدار» — برای value type و با override می‌تواند فرق کند.
- استفادهٔ بی‌رویه از **ref/out** به‌جای بازگشت مقدار یا شیء.
- استفادهٔ **ArrayList** به‌جای **List\<T\>** در کد جدید.

---

## 5. When to Use / When NOT to Use

- **struct**: دادهٔ کوچک، سبک، بدون هویت مشترک؛ نه برای موجودیت‌های بزرگ یا وقتی ارث‌بری از کلاس لازم است.
- **Abstract Class**: وقتی یک پایهٔ مشترک با منطق و فیلد داری؛ **Interface**: وقتی فقط قرارداد و چند نوع رفتار می‌خواهی.
- **IQueryable**: منبع خارج از حافظه (دیتابیس) و نیاز به ترجمهٔ کوئری؛ **IEnumerable**: دادهٔ درون‌حافظه.
- **StringBuilder**: ساخت یا تغییر مکرر رشته؛ **string**: رشتهٔ ثابت یا تغییر کم.
- **out**: خروجی چندگانه یا الگوی Try؛ **ref**: وقتی هم ورودی هم خروجی می‌خواهی و مقدار اولیه داری.
