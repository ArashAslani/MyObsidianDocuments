## Value Type vs Reference Type

**Value types:** primitive types (مثل int, bool) و struct ها. این‌ها در stack ذخیره می‌شوند.
**Reference types:** class ها، delegate ها، interface ها و آرایه‌ها. این‌ها در heap ذخیره می‌شوند و فقط آدرس (reference) آن‌ها در stack است.

Stack LIFO هست و به خاطر اینکه نمیدانیم مقادیر ref types چقدر فضا میگیرند و ممکن است منابع stack را بگیرند پس در heap ذخیره میشوند.

## Strings

string ها ref type هستند. چون مشخص نیست چه حجمی دارند و چند کاراکتر باشند. مقدار پیشفرض آن null هستند.
و thread-safe هستند چون immutable هستند و غیر قابل تغییر هستند.
![[Pasted image 20240214135918.png]]

زمانی که به یک string مقدار جدید میدهیم مقدار قبلی باقی میماند و اشاره گر به مقدار جدید در هیپ اشاره میکند.
و مقدار قبلی توسط GC از بین میرود.

string ها **interning** انجام می‌دهند چرا که اگر دو متغیر string با نام های متفاوت و مقادیر یکسان ایجاد کنیم جفت اسامی روی یک ادرس در هیپ اشاره میکنند.
![[Pasted image 20240214140927.png]]

حالا چطور این اتفاق می‌افتد؟

**ساختار Heap:** heap به بخش‌های مختلف تقسیم می‌شود:
- **SOH (Small Object Heap):** برای آبجکت‌های کوچک‌تر از ۸۵ کیلوبایت
- **LOH (Large Object Heap):** برای آبجکت‌های بزرگ‌تر یا مساوی ۸۵ کیلوبایت (مثل آرایه‌های بزرگ)
- **Loader Heap:** برای metadata نوع‌ها و Method Table ها

**نکته مهم:** string ها معمولاً در **SOH** ذخیره می‌شوند، نه LOH. فقط رشته‌های بسیار بزرگ (>85KB) به LOH می‌روند.

string ها از **String Interning** استفاده می‌کنند: در زمان allocation، اگر مقدار مشابهی از قبل وجود داشته باشد، به همان reference برمی‌گردد؛ وگرنه یکی جدید ساخته می‌شود.

## پلتفرم .NET

زمانی که یک کد را با C# مینویسم فارغ از اینکه در چه حوزه ای هست(consol , asp.net , ... ) کامپایلری به نام Roslyn وجود دارد که کد هارا به IL تبدیل میکند.
این کد روی ماشین اجرا نمیشود.
قبل از تبدیل به IL در فضای Compile time هستیم.
زمانی که این کد روی ماشین میخواهد execute شود.
در فضای Runtime یک کامپایلر دیگر وجود دارد. یعنی CLR شامل کامپایلری هست به نام JIT(just in time) که دیگر تفاوتی نکند برای چه os ای کد سی شارپ بزنیم.
برای C# یکسری Runtime متفاوت برای سیستم عامل های مختلف وجود دارد که هر کدام JIT مخصوص خود را دارند که میداند کد IL چطور روی یک سیستم عامل بخصوص اجرا کند.
کد IL فارغ از سیستم عامل هست.
در کنار CLR یک BCL قرار دارد. کهBCL هم نسبت به OS متفاوت هست چرا که ممکن هست هر سیستم عاملی رفتاری متفاوت روی list , dic ,...  و داشته باشند.
BCL : base class library
CLR : common language runtime
.net شامل CLR و BCL هست. و لایه اپلیکیشن میتواند نباشد که به آن معماری runtime میگوید. که شبیه JVM جاوا هست.
![[Pasted image 20240215211200.png]]

تمام زبان های مایکروسافتی از یک سیستم runtime استفاده میکنند و مهم نیست از چه زبانی استفاده میشود.
.net یک unified development platform هست.
![[Pasted image 20240215212144.png]]

خود CLR شامل دو کامپوننت اصلی است: **CLS** و **CTS**.
CLS : Common language specification 
به ازای هر زبانی شامل مقررات اون زبان هست. مثلا یک زبان لازم هست سمیکالون بزاریم تو یکی نه.

CTS : Common type system
مثلا در vb متغیر int به صورت integer هست در C# به صورت int که تشخیص میدهد تمام اینها چی هستن و تمام انها را مثلا به int32 تبدیل میکند. یعنی کار با varibles ها با این قسمت هست.
همچنین تشخیص اینکه هر متغیر در چه جایی از حافظه قرار بگیرد کار این بخش از CLR هست.

**IEnumerable**

⚠️ **نکته مهم:** IEnumerable از IEnumerator ارث‌بری **نمی‌کند**. متد `GetEnumerator()` دارد که یک `IEnumerator` برمی‌گرداند.

`IEnumerable` برای پیمایش read-only مناسب است و معمولاً با `yield` و lazy evaluation استفاده می‌شود.

## نکات کلیدی برای مصاحبه

### سوال‌های رایج

1. **Value type vs Reference type؟**
   - Value: در stack، کپی می‌شوند. مثال: int, struct
   - Reference: در heap، آدرس در stack. مثال: class, string

2. **Boxing و Unboxing؟**
   - Boxing: value type به object (ref type) – implicit
   - Unboxing: object به value type – explicit، ریسک InvalidCastException

3. **تفاوت ref و out؟**
   - ref: ورودی/خروجی، باید مقداردهی اولیه شود
   - out: خروجی، حتماً داخل متد assign شود

4. **IEnumerable vs IList؟**
   - IEnumerable: پیمایش read-only، lazy، مناسب وقتی فقط iterate می‌کنیم
   - IList: random access، Add/Remove، مناسب وقتی تغییرات داریم

5. **string immutable است؟**
   - بله. هر تغییر یک string جدید می‌سازد. thread-safe است.

6. **Record چه مزیتی دارد؟**
   - Immutable به صورت پیش‌فرض، value-based equality، با `with` برای copy با تغییر

### اشتباهات رایج

❌ "IEnumerable از IEnumerator ارث می‌برد" – غلط، متد `GetEnumerator()` دارد
❌ "string ها در LOH ذخیره می‌شوند" – غلط، در SOH (مگر خیلی بزرگ باشند)
❌ "struct همیشه در stack است" – غلط، اگر داخل class باشد در heap است
