# زبان Declarative در برابر Imperative و چرخهٔ کوئری

## 1. Interview Relevance Summary

تو مصاحبه ممکنه بپرسن **تفاوت زبان Declarative و Imperative** رو در زمینهٔ دیتابیس و کوئری. این فایل همان مفهوم رو خلاصه می‌کنه و به **چرخهٔ عمر کوئری** در SQL Server اشاره می‌کنه. برای سینتکس و JOIN و تراکنش به **[[SQL]]** و **[[database more]]** مراجعه کن.

---

## 2. Declarative در برابر Imperative

- **Declarative (اعلامی)**: فقط می‌گی **چه می‌خوای**؛ نحوهٔ انجام کار بر عهدهٔ موتور است. مثلاً در **SQL** می‌نویسی `SELECT ... WHERE ...` و موتور تصمیم می‌گیره چطور اسکن کند، از کدوم ایندکس استفاده کند و غیره.
- **Imperative (دستوری)**: قدم‌به‌قدم می‌گی **چیکار کن**: مثلاً با **ADO.NET** connection باز می‌کنی، کوئری می‌نویسی، ارسال می‌کنی، نتیجه رو می‌خونی و بستن connection را خودت انجام می‌دی.

یه تشبیه: Declarative مثل تاکسی است — مقصد رو می‌گی و راننده مسیر و نحوهٔ رانندگی رو انتخاب می‌کنه. Imperative مثل رانندگی خودت است — هر تصمیم با توئه.

---

## 3. چرخهٔ عمر کوئری (خلاصه)

وقتی کاربر یه **درخواست** به SQL Server می‌فرسته، به‌طور خلاصه این مراحل طی می‌شن:

1. **بررسی گرامر (Parse)**: سینتکس کوئری چک می‌شه.
2. **بررسی متغیرها و وجود اشیاء**: نام جدول‌ها، ستون‌ها و دیتابیس معتبرن؟
3. **بهینه‌ساز و اجرا**: موتور (engine) پلن اجرا رو انتخاب می‌کنه و کوئری رو اجرا می‌کنه.
4. **نتیجه** به client برگردونده می‌شه.

جزئیات بیشتر (Algebrizer، Optimizer، Plan Cache) در **[[Explain Plan]]** آمده.

---

## 4. Key Interview Talking Points

- **Declarative**: «چی می‌خوام» (مثل SQL)؛ موتور «چطور» را تعیین می‌کنه.
- **Imperative**: «چیکار کن» قدم‌به‌قدم (مثل ADO.NET با باز/بستن connection و ارسال دستور).
- **چرخهٔ کوئری**: Parse → بررسی معنایی و اشیاء → بهینه‌ساز و اجرا → نتیجه.
