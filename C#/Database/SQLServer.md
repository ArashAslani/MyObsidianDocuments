# SQL Server: نصب و مفاهیم اولیه

## 1. Interview Relevance Summary

این فایل **مفاهیم اولیهٔ کار با SQL Server** رو پوشش می‌ده: نصب، ساخت دیتابیس و جدول، نوع داده‌ها، کلید اصلی، ایندکس و محدودیت. برای مصاحبهٔ Backend معمولاً انتظار نمی‌ره جزئیات UI را حفظ باشی، ولی تفاوت نوع داده‌ها (مثلاً varchar در برابر nvarchar)، Primary Key، ایندکس و Check Constraint رو بدونیش خوبه. برای ایندکس و تیونینگ عمیق‌تر به **[[Database]]** و **[[Tuning Database]]** مراجعه کن.

---

## 2. نصب و دسترسی

دیتابیس **SQL Server** به‌صورت موتور (Engine) روی سیستم نصب می‌شه؛ بعد با **SQL Server Management Studio (SSMS)** می‌تونی به‌صورت گرافیکی به دیتابیس‌ها، جدول‌ها و تنظیمات وصل بشی و مدیریت کنی.

---

## 3. ساخت دیتابیس و جدول

وقتی یه دیتابیس جدید می‌سازی، به‌طور پیش‌فرض چند پوشه داره: مثلاً **Database Diagrams** (برای کشیدن دیاگرام از جدول‌ها)، **Tables** (جداول پروژه) و غیره.

برای هر **ستون** در جدول باید **نوع داده (Data Type)** و در صورت نیاز **Allow Null** رو مشخص کنی (تیک Allow Null = اجازهٔ خالی بودن؛ بدون تیک = اجباری).

---

## 4. نوع داده‌های متداول

| نوع | توضیح کوتاه |
|-----|-------------|
| **bigint** / **int** | عدد صحیح |
| **char(n)** | رشته با طول ثابت؛ فضای خالی با padding پر می‌شه |
| **nchar(n)** | مثل char ولی برای یونیکد (Unicode) |
| **varchar(n)** | رشته با طول متغیر؛ به‌اندازهٔ واقعی فضا می‌گیره |
| **nvarchar(n)** | مثل varchar ولی یونیکد |
| **binary** | دادهٔ باینری |
| **bit** | دو حالت ۰ و ۱ (معمولاً برای مقدار boolean) |
| **datetime** | تاریخ و زمان (بسته به تنظیمات سرور، اغلب بدون offset) |
| **datetimeoffset** | تاریخ و زمان به‌همراه اختلاف با UTC |

**نکته**: نوع **image** برای ذخیرهٔ فایل منسوخ شده؛ برای فایل‌های بزرگ معمولاً از **FILESTREAM** یا ذخیرهٔ خارج از دیتابیس استفاده می‌کنن.

---

## 5. Primary Key و ایندکس

- **Set Primary Key**: با راست‌کلیک روی ستون یا از طریق Design جدول می‌تونی یک یا چند ستون رو به‌عنوان **کلید اصلی** تعیین کنی. به‌طور پیش‌فرض معمولاً یه **Unique Clustered Index** روی همون ستون‌ها ساخته می‌شه.
- **ایندکس اضافه**: راست‌کلیک روی جدول → Indexes/Keys → اضافه کردن ایندکس جدید. با انتخاب ستون و **Create as Clustered** (یا Nonclustered) جستجو بر اساس اون ستون‌ها سریع‌تر می‌شه. برای ترتیب و تعداد ایندکسها به **[[Database]]** و **[[Tuning Database]]** مراجعه کن.

---

## 6. Constraints (محدودیت‌ها)

با **Add** در Design جدول یا از طریق Constraint می‌تونی محدودیت اضافه کنی. در **Check Constraint** با **Expression** (به زبان SQL) شرط رو می‌نویسی (مثلاً `Age >= 0`). می‌شه از یه **Function** هم داخل Expression استفاده کنی، ولی معمولاً مستقیم نوشتن شرط ساده‌تر و برای بهینه‌ساز سریع‌تره.

---

## 7. Function و Stored Procedure

- **Scalar Function**: از **Programmability → Functions → Scalar-valued** می‌تونی تابعی تعریف کنی که یه مقدار برمی‌گردونه. بار اول با **CREATE** ساخته می‌شه؛ برای هر تغییر بعدی از **ALTER** استفاده می‌کنی.
- **Stored Procedure**: روال‌های ذخیره‌شده روی سرور؛ برای منطق چندمرحله‌ای و کاهش رفت‌وآمد با client به‌کار می‌رن. جزئیات و سناریوهای استفاده در فایل‌های دیگر همین پوشه (مثلاً **[[database more]]**) آمده.

---

## 8. Key Interview Talking Points

- **نوع داده**: varchar در برابر nvarchar (یونیکد و فضا)؛ datetime در برابر datetimeoffset (با/بدون time zone).
- **Primary Key** و پیش‌فرض Clustered Index؛ ایندکس برای بهبود جستجو.
- **Check Constraint** برای اعتبار داده در سطح جدول؛ Expression مستقیم معمولاً بهتر از فراخوانی function توی constraint.
