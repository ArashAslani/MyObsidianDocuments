نحوه ذخیره سازی داده در SQL Server 
![[Pasted image 20240423210602.png]]
وقتی جدولی در دیتابیس ایجاد میکنیم و قسط داریم که یک رکورد در ان درج کنیم باید در دیسک نوشته شود.
Sql server برای اینکه داده را روی دیسک بنویسد از Page استفاده میکند.
Page بسته های اطلاعاتی 8Kb هستن که داده داخل این بسته های 8Kb ذخیره میشوند.
همونطور که در شکل میبینیم هر بسته شامل بخش های :
	Page Header : Next and Previous Pages address 
	Row Offset : Current Page Address
	Free Space
فضایی که هر پیج میتواند برای دیتا اخصاص دهد 8086 Bytes هست.
پس باید در طراحی جداول این دقت را داشت که دیتا بتواند به بهترین شکل از فضای Pages استفاده کنند.
پس مفهوم Page یک بسته 8Kb هست که میتواند دیتا را داخل خودش نگه داری کند.
جدولی که ایجاد میکنیم میتواند دو نوع باشد :
![[Pasted image 20240423212610.png]]
جدول Heap : 
	زمانی که جدولی ایجاد میکنیم در مرحله اول جدولی ایجاد شده که ساختاری ندارد و زمانی که فرضا 100 رکورد داخل آن اضافه میشود، Sql Server بدون توجه به نحوه چینش فیزیکی و منطقی رکورد ها آن هارا ذخیره سازی میکند. در نتیجه زمانی که روی جدول Select میزنیم Sql Server باید روی تمام جدول اسکن انجام دهد تا رکورد مد نظر مارا واکشی کند.
	Cluster Index :
		 برای سرعت بخشیدن به واکشی داده ها از جداول استفاده میشوند.
		به دو نوع Clustered و Non-Clustered هستند.
		زمانی که روی یک جدول Clustered index ایجاد میکنیم (PK) در واقع Sql Server رکورد های جدول را به صورت فیزیکی چینش آنها را به صورت مرتب و پشت سر هم   انجام میدهد.
		مانند صفحات کتاب به خاطر همین بیشتر از 1 Clustered index نمیتوانیم داشته باشیم. 
	Non-Clustered index :
	 مانند ایندکس پایان کتاب هست. که کلید (کلمات) رو به صفحات کتاب تخصیص میدهد. که در واقع Sql server چینش منطقی یک Column هست که تعیین شده هست.
	 مثل ایندکس کردن جدول بر اساس کد ملی یا ایمیل.
	 در واقع کلید را به جدول Bind میکند. به صورتی که جدول مرتب شده با Columns مشخص شده در فضای دیگری از دیسک به صورت مجازی ایجاد میشود.
	 به طور مثال مشخص میکند کلمه پرستار در صفحه 16 - 15 از کتاب ذخیره شده است.

مثال :

```sql
USE master;
GO

CREATE DATABASE Sales ON
(NAME = Sales_dat,
    FILENAME = 'C:\Program Files\Microsoft SQL Server\MSSQL16.MSSQLSERVER\MSSQL\DATA\saledat.mdf',
    SIZE = 10,
    MAXSIZE = 50,
    FILEGROWTH = 5)
LOG ON
(NAME = Sales_log,
    FILENAME = 'C:\Program Files\Microsoft SQL Server\MSSQL16.MSSQLSERVER\MSSQL\DATA\salelog.ldf',
    SIZE = 5 MB,
    MAXSIZE = 25 MB,
    FILEGROWTH = 5 MB);
GO


```

2.Algebrizer
![[Pasted image 20240423233922.png]]در واقع در این مرحله جدول مورد نظر را بررسی میکند که دیتابیس کجای دیسک هست. پیج ها بررسی میشوند و پارتیشن دیتابیس پیدا میشود که بعد از آن جدول را داخل رم می آورد. (شناسایی دیتابیس)
بعد از آن زمانی که کوئری اجرا میشود یک Hash تولید میشود. 

و بعد از آن یک Query Processor Tree ایجاد میشود و به مرحله Query Optimizer می رود.
تا بعد از محاسبه چندین Plan روشی  (Plan) که Cost کمتر و Benefit بیشتری دارد پیدا کند.
اگر Plan از قبل وجود داشت این مرحله دوباره اجرا نمیشود و از Plan قبلی که در Plan Cache ذخیره شده استفاده میکند.
یکی از چند صد قسمت اسلات رم وظیفه ذخیره سازی Plan Cache را دارد.

زمان ایجاد پلن موارد زیر چک میشود :
1. ایندکس مورد استفاده کوئری
2. ترتیب اجرا کوئری های Join دار
3. هزینه اجرای هر بخش از کوئری
4. تاثیر Constraints ها بر کوئری
5. مرتب سازی (به ازای هر Order By یک کامپوننت Sort ایجاد میکند)
