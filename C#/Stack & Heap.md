سیستم عامل و net CLR. حافظه را به دو بخش stack و heap تقسیم بندی می‌کنند.

//////////////////////////Stack//////////////////////////
Stack یا پشته همان Static memory هست که در بخش user-space قرار دارد و به صورت خودکار توسط CPU مدیریت میشود. 

Stack از بخش CPU Cache بهره میبرد فضای محدودی (چند مگ) دارد. در عوض واکشی اطلاعات به دلیل تخصیص فقط یک اشاره گر بسیار سریع و آسان است.

Stack دارای یک الگوی ثابت LIFO(Last In First Out) برای ذخیره اطلاعات است و طول عمر حافظه تخصیص داده شده به متغیر ها در حد یک بلاک در برنامه نویسی هست. به همین دلیل Fragmentation (قطعه قطعه شدن) در این حافظه اتفاق نمی افتد.

![[Pasted image 20230918200421.png]]

این ساختمان داده در Memory نگهداری میشود.

Stack چون دارای یک ساختار مشخص هست، تمامی متغیر ها باید در ابتدا مقدار دهی شوند (نوع داده باید مشخص شود) و در غیر این صورت خطای کامپایلر رخ میدهد.

البته در C# با قابلیت Nullable type امکان تخصیص مقدار null در متغیر های محلی مهیا شده.

thread ها یا Value type یا توابع و مقدار Return آنها در stack قرار می گیرند. و تغیرهای محلی (Local Variable ها)، پارامترهای ورودی متد و مقدار بازگشتی یک متد، جز مواردی هستند که مقادیرشان داخل Stack قرار میگیرد.

از خطاهایی که ممکن در اثر استفاده نادرست از stack صورت بگیرد خطای stack overflow هست که ممکن است به دلیل سرریز اطلاعات به دلیل استفاده ازمتغیر های محلی حجیم صورت بگیرد که باعث کاهش فضای آزاد و تخریب (corrupt) شدن بخشی از مموری شود.

**StackOverflowException** : فضای Stack محدود است. این فضا در سیستم‌های 32 بیت برابر با 1 مگابایت و در سیستم‌های 64 بیت برابر با 4 مگابایت است ([Reference](https://stackoverflow.com/a/28658130/6661314)). اگر حجم متغیرهایی که روی استک Push میشوند، این محدودیت را رد کنند و یا اگر یک متد بطور دائم خودش را صدا بزند (Recursive) و هیچگاه از آن خارج نشود، با خطای StackOverflowException مواجه میشوید.


//////////////////////////Heap//////////////////////////
Heap یا همان Dynamic memory هست که در بخش user-space حافظه مجازی قرار دارد و باید به صورت دستی توسط برنامه نویس مدیریت شود. 

وقتی یک متغیر از نوع string را ایجاد میکنیم، مقدار آن داخل Heap و Memory-Address آن متغیر روی Heap، در Stack نگه داری میشود.

Heap برعکس stack قائده خاصی برای ذخیره اطلاعات ندارد(ساختار، ترتیب و Layout خاصی ندارد.) همچنین دارای فضای بیشتری برای ذخیره اطلاعات است و البته به دلیل مراحل تخصیص مقدار در حافظه (جستوجوی مکان (Block-بلاک-) با اندازه مناسب آبجکت برای ذخیره و بعد رزرو فضا و در نهایت تخصیص داده به حافظه (Allocating) و در نهایت assign آدرس به stack) کندتر عمل میکند.
![[Pasted image 20230918200621.png]]

تخصیص حافظه در Heap توسط سیستم عامل و Heap Manager صورت میگیرد و نکته که در تخصیص حافظه وجود دارد تنها نباید بلاکی با بلاک ها تداخل یا Overlap داشته باشند. به بلاک های در حال استفاده In Use و به فضاهای خالی Free میگویند.

زمانی که یک Reference type را new میکنیم مقدار آن در Heap و آدرس آن در stack قرار میگیرد. و زمانی که کار ما با آن تمام میشود توسط [[Garbage Collector]] فضا آزاد (Clean) و آبجکت ها حذف (Deallocation) میشود.

Heap مربوط به زمان اجرا (Runtime) (تخصیص بافر array به صورت داینامیک در زمان اجرا صورت میگیرد و مانند stack نمیباشد) دارای طول عمری بیشتری هستند و با اتمام کار آزاد نمی شوند. 

مدیریت Heap در زبان های سطح پایین توسط برنامه نویس و در C# و Java به ترتیب با CLR و JVM وظیفه کنترل حافظه را دارند.

در صورتی که در آزاد سازی Heap دقت صورت نگیرد هرچه بیشتر از برنامه استفاده شود آبجکت های بیشتری ایجاد میشوند و در نتیجه مشکلی به نام نشت حافظه یا Memory Leak صورت میگیرد که در برنامه نویسی با زبان C++ بسیار شایع است.
